# Summit Race

**Demo:** <https://peakbuild112000.github.io/Project1/>  
**Repository:** <https://github.com/peakbuild112000/Project1>  
**Engine:** Godot 4.6.1 stable

A hard, fast, physics-driven 3D climbing race for 2–4 players. Everyone starts at
the same flat pad at the foot of a seeded procedural mountain. The first climber
to touch the summit wins immediately. Falls cost five seconds, not health.

> The Web build supports online multiplayer through WebRTC. Browsers do not
> allow ENet/UDP sockets, so Web rooms need a small WebSocket signaling server
> (included in `tools/`). There is no solo mode: every match needs at least two
> players.

## Demo

The GitHub Pages build is published at:

<https://peakbuild112000.github.io/Project1/>

Recommended browser: a recent Chrome, Edge, Firefox or Safari with WebGL2
enabled. Use **HOST ROOM** / **JOIN ROOM** with a signaling URL and a shared
room code for online play. Desktop builds use ENet host/join on UDP port `7777`.

## Features

- Two independent grappling hands with ropes, winch, swing, rappel and mantle.
  Arm reach is deliberately short (14 m), so holds must be earned one by one.
- A flat shared start pad and four evenly spaced spawn slots, so no racer begins
  on a slope or inside the mountain.
- Stamina drains while hanging or climbing and refills only on solid ground.
  There is no health bar, injury state, locked stamina slice or effort meter.
- Falls below the world limit respawn at the racer's last checkpoint and add a
  five-second time penalty. Ragdoll is only a short stumble that always
  recovers; it has no downed state and no revival step.
- Four trampolines launch climbers toward the next route section. Two jetpack
  pickups refill a single equipment slot; an empty jetpack can be removed.
- Checkpoints at 26 m, 64 m and 104 m save the respawn point. Wind gusts,
  brittle holds, moving platforms and patrolling enemy drones get harder near
  the summit.
- A narrow alternate spire with small sloped holds, wide gaps and sharp
  overhangs offers a harder route.
- A live altitude leaderboard and a 300-second race timer. Touching the summit
  ends the match immediately with reason `SUMMIT`; if time runs out, the best
  score wins with reason `TIME UP`.
- Low-poly GLB models (jetpack, trampoline, rock, enemy) generated by a Blender
  / bforartists script. Procedural sound effects.

## Run from source

Install Godot 4.6.1 or newer, then open the project folder.

PowerShell example:

```powershell
$godot = "C:\Users\PC\Desktop\Godot\Godot_v4.6.1-stable_win64_console.exe"
$project = "C:\Users\PC\Documents\project-1"

& $godot --headless --path $project --editor --quit
& $godot --path $project
```

The main menu opens first.

- **HOST** opens an ENet server on the chosen port (`7777` by default). Ask
  friends to join your IP.
- **JOIN** connects to a host. Guests click **READY**; the host clicks
  **START MATCH** directly.
- LAN works out of the box. Online desktop play needs port forwarding or a
  tunnel for UDP `7777`, or any port selected in the menu.
- The start button unlocks only when at least two players are in the lobby.
  There are no classes, ready-gated roles or manual class selectors.

## Rules

- The summit is at 142 m. First climber to touch its hazard wins immediately.
- A match lasts 300 seconds. If nobody reaches the summit, the winner is the
  racer with the highest score: `altitude × 10 − penalties`.
- Falling below `y = -12` respawns you at your highest checkpoint and adds
  `5.0` seconds to your penalty. There are no lives and no spectator state.
- Checkpoints at 26 m, 64 m and 104 m update the respawn point.
- Enemy hits and wind gusts drain stamina and briefly stun; they never cause
  permanent damage. Stamina refills only while standing on solid ground.
- Emptying the stamina bar releases your anchors and shows `EXHAUSTED`. A
  ragdoll from a stumble lasts a few seconds and then recovers automatically.
- Reach the summit with the best route you can find: the main mountain face,
  the narrower hard spire, trampoline launches and jetpack boosts are all
  valid.

## Race objects and strategy

- **Trampolines** are fixed boost pads. They launch any climber who touches
  their bounce zone and are not grappleable or carryable.
- **Jetpack** is the only pickup. Pick it up once, hold `Shift` to fly briefly,
  refill the same slot later, and press `G` to drop it when empty.
- **Enemy drones** patrol fixed local loops. Each peer applies its own hit
  locally, so no network RPC is needed for them.
- **Difficult pillar** is a narrow alternate spire with tiny brittle holds and
  sharp overhangs for racers who want the risky line.

The host broadcasts trampoline transforms at 20 Hz so every peer sees the same
boost pads.

## Multiplayer architecture

- `Net` wraps two transports: `ENetMultiplayerPeer` on desktop and
  `WebRTCMultiplayerPeer` on Web. Both expose the same authoritative RPC flow.
- Web rooms use `scripts/network/web_rtc_room.gd`: a WebSocket signaling client
  assigns ids, relays SDP offers/answers and ICE candidates, then game packets
  travel directly between browsers. The host is always peer id `1`.
- Each peer simulates its own `RigidBody3D` climber. Remote climbers are frozen
  kinematic bodies that interpolate toward `replicated_position` and
  `replicated_yaw`; the synchronizer never writes physics transforms directly.
- The host owns the countdown, timer, checkpoints, scores, winner, chat relay,
  item pickups and prop state. Falls add a time penalty; there are no lives.
- Item RPCs: `rpc_request_item`, `rpc_item_taken`.
- Prop RPC: `rpc_prop_states` broadcasts the fixed trampoline transforms.
- `MultiplayerSpawner` uses `spawn_path = NodePath("../Players")`.
- Replication paths use `NodePath(".:property")`.

See `docs/DESIGN.md` for the full contract.

## Web export

The repository includes `export_presets.cfg` with a `Web` preset. Export command:

```powershell
$godot = "C:\Users\PC\Desktop\Godot\Godot_v4.6.1-stable_win64_console.exe"
$project = "C:\Users\PC\Documents\project-1"
$out = "$env:TEMP\opencode\web-demo\index.html"

& $godot --headless --path $project --export-release "Web" $out
```

The published demo lives on the `gh-pages` branch. Rebuild and publish it with:

```powershell
$demo = "$env:TEMP\opencode\web-demo"
git worktree add "$env:TEMP\opencode\gh-pages" gh-pages
Copy-Item "$demo\*" "$env:TEMP\opencode\gh-pages" -Recurse -Force
New-Item "$env:TEMP\opencode\gh-pages\.nojekyll" -ItemType File -Force | Out-Null
```

ENet is desktop-only. Online Web rooms need the included signaling relay,
because browsers cannot open UDP sockets:

```powershell
cd tools
npm install
npm start
```

The relay listens on port `9080` by default (`PORT` and `HOST` can be changed
through environment variables). Enter its public URL in the Web menu, for
example `ws://localhost:9080` for local testing or `wss://your-host/signal`
behind an HTTPS reverse proxy. An HTTPS page must use a `wss://` URL because
browsers block mixed content.

One player clicks **HOST ROOM** with a room code (3–12 letters or digits).
Friends enter the same code and click **JOIN ROOM**, up to 4 players. The
**READY** and **START MATCH** flow is unchanged. The signaling server never sees
gameplay packets; it only forwards WebRTC offers, answers and ICE candidates.
It is not bundled with GitHub Pages, so you need to host it separately to play
online from the published demo. The included transport uses public Google STUN
servers; players behind very restrictive NATs may need a TURN server added to
`ICE_SERVERS` in `scripts/network/web_rtc_room.gd`.

## Validation

Run every local check:

```powershell
.\tests\run_tests.ps1
```

Expected summary:

```text
NO SOLO failures=0
REMOTE VISUAL failures=0
UPRIGHT failures=0
CAMERA YAW failures=0
CLIMB VALIDATION failures=0
GAME SMOKE failures=0
STATIC BAD: 0
EMPTY FILES: 0
RESULT PASSED
```

The two-process ENet harnesses additionally verify host/join and remote racer
state over UDP port `7792`:

```powershell
$exe = "C:\Users\PC\Desktop\Godot\Godot_v4.6.1-stable_win64_console.exe"
$proj = "C:\Users\PC\Documents\project-1"
$tmp = "$env:TEMP\opencode"

$serverProc = Start-Process -FilePath $exe -ArgumentList @("--headless", "--path", $proj, "--script", "$tmp\climb_net_host_test.gd") -PassThru -NoNewWindow
Start-Sleep -Seconds 2
$clientProc = Start-Process -FilePath $exe -ArgumentList @("--headless", "--path", $proj, "--script", "$tmp\climb_net_client_test.gd") -PassThru -NoNewWindow
Wait-Process -Id $serverProc.Id, $clientProc.Id -Timeout 90
```

Do not replace those precise PIDs with a wildcard `Stop-Process` call.
